1. Логические соедния в SQL

Во всех ранее рассмотренных примерах демонстрировались разнообразные средства спецификации простых запросов. Все рассмотренные приемы построения простых запросов могут быть использованы не только в чистом виде, но и во всех возможных сочетаниях друг с другом.

Рассмотренные типы запросов можно назвать простыми, поскольку все они использовали в качестве источника данных одну таблицу. В реальных информационных задачах гораздо чаще запросы адресуются не к одной, а к нескольким связанным таблицам, которые представляют все разнообразие данных конкретной предметной области. В реальных задачах выборка данных осуществляется из нескольких связанных между собой таблиц.

Естественное соединение

В запросах выборки из связанных таблиц предложение SELECT задает структуру выборки, где FROM – источник данных, WHERE – условное соединение.

Естественное условие содержит следующий формат записи:

Листинг 33 – Формат записи естественного соединения

<имя таблицы1>.<имя столбца1>
<оператор>
<имя таблицы2>.<имя столбца2>

Здесь оператор — это один из операторов сравнения.

Важным частным случаем соединения является так называемое эквисоединение — соединение по условию равенства столбцов, по которым устанавливается связь между таблицами.

Пример. Вывести естественным соединением таблицы «Кафедра» и «Специальность»

Листинг 34 - Эквисоединение

SELECT Кафедра.*, Специальность.*
FROM Кафедра, Специальность
WHERE Кафедра.шифр = Специальность.шифр

Важной разновидностью соединения является так называемое естественное соединение, или эквисоединение без дублей одноименных столбцов (полей). Операция естественного (внутреннего) соединения лежит в основе большинства выборок из связанных таблиц.

Запросы на соединение таблиц можно выполнить через операцию INNER JOIN:

Условие соединение INNER JOIN

Листинг 35 – Операция INNER JOIN

SELECT <список полей>
FROM <имя таблицы1>
INNER JOIN < имя таблицы2> ON <имя таблицы1>.<имя столбца1> = <имя таблицы2>.<имя столбца2>;

Операцию INNER JOIN можно использовать в любом предложении FROM. Это самые обычные типы связывания. Они объединяют записи двух таблиц, если связующие столбцы обеих таблиц содержат одинаковые значения. Обязательным условием корректного соединения является совместимость типов столбцов, по которым осуществляется связь.

Левое соединение – LEFT JOIN

Запрос на соединение через LEFT JOIN выглядит следующим образом:

Листинг 36 – Операция LEFT JOIN

SELECT <список полей>
FROM <имя таблицы1>
LEFT JOIN < имя таблицы2> ON <имя таблицы1>.<имя столбца1> = <имя таблицы2>.<имя столбца2>;

Операцию LEFT JOIN можно использовать в любом предложении FROM. Этот тип соединения возвращает все записи из левой таблицы (таблицы1), даже если в правой таблице (таблицы2) нет соответствующих записей. Если связующий столбец правой таблицы не содержит значения, совпадающего со значением в левой таблице, то для столбцов правой таблицы в результирующем наборе будут подставлены значения NULL. Обязательным условием корректного соединения является совместимость типов столбцов, по которым осуществляется связь.

Правое соединение– RIGHT JOIN

Запросы на соединение таблиц при правом соединении можно выполнить через операцию RIGHT JOIN:

Листинг 37 – Операция RIGTH JOIN

SELECT <список полей>
FROM <имя таблицы1>
RIGHT JOIN < имя таблицы2> ON <имя таблицы1>.<имя столбца1> = <имя таблицы2>.<имя столбца2>;

Операцию RIGHT JOIN можно использовать в любом предложении FROM. Этот тип соединения возвращает все записи из правой таблицы (таблицы2), даже если в левой таблице (таблицы1) нет соответствующих записей. Если связующий столбец левой таблицы не содержит значения, совпадающего со значением в правой таблице, то для столбцов левой таблицы в результирующем наборе будут подставлены значения NULL. Обязательным условием корректного соединения является совместимость типов столбцов, по которым осуществляется связь.

Перекрестное соединение – CROSS JOIN

Перекрестное соединение можно выполнить через операцию CROSS JOIN:

Листинг 38 – Операция CROSS JOIN

SELECT <список полей>
FROM <имя таблицы1>
CROSS JOIN <имя таблицы2>

Операцию CROSS JOIN можно использовать в любом предложении FROM. Этот тип соединения возвращает декартово произведение записей двух таблиц, то есть каждую запись из таблицы1 соединяет с каждой записью из таблицы2. Количество строк в результате равно произведению количества строк первой таблицы на количество строк второй таблицы. В отличие от других типов соединений, CROSS JOIN не требует условия связывания (предложения ON). Обязательным условием корректного выполнения является отсутствие синтаксических ошибок в запросе.

В декартовом произведении выводятся все возможные комбинации строк-кортежей перемножаемых таблиц, даже такие, которые не имеют смысла в моделируемой предметной области.

Декартово произведение можно выполнить без использование оператора CROSS JOIN:

Листинг 39 – Декартово произведение без использования оператора CROSS

SELECT <список полей>
FROM <имя таблицы1>, <имя таблицы2>

Полное соединение – FULL OUTER JOIN

Запросы на соединение таблиц при правом соединении можно выполнить через операцию FULL OUTER JOIN:

Листинг 40 – Операция FULL OUTER JOIN

SELECT <список полей>
FROM <имя таблицы1>
RIGHT JOIN < имя таблицы2> ON <имя таблицы1>.<имя столбца1> = <имя таблицы2>.<имя столбца2>;

Операцию FULL OUTER JOIN можно использовать в любом предложении FROM. Этот тип соединения объединяет результаты LEFT JOIN и RIGHT JOIN. Он возвращает все записи из обеих таблиц: строки, где есть совпадения по связующим столбцам, а также строки из левой таблицы без соответствий в правую и строки из правой таблицы без соответствий в левой.

Если для какой-либо таблицы нет совпадающих записей, то для её столбцов в результирующем наборе подставляются значения NULL. Обязательным условием корректного соединения является совместимость типов столбцов, по которым осуществляется связь.

2. Подзапросы

Подзапрос (вложенный запрос) – это запрос, который вложен внутрь другого SQL – запроса (внешнего или основного). Его результат используется основным запросом для дальнейших операций. Подзапрос всегда заключается в круглые скобки и выполняется первым, до внешнего запроса

Существуют следующие типы подзапросов:

1. По способу получения результата:

— Простой;

— Коррелированный.

2. По виду результата:

— Скалярный (возвращает одно единственное значение)

— Строковый (возвращает множество значений нескольких столбцов)

— Табличный (возвращает множество значений из одного или нескольких столбцов таблицы)

Простые подзапросы характеризуются тем, что они формально никак не связаны с содержащими их внешними запросами. В случае запроса с простым подзапросом сначала выполняется полностью подзапрос, а затем его результат используется в объемлющем запросе.

Подчиненный запрос можно использовать вместо выражения в списке полей инструкции SELECT или в предложениях WHERE и HAVING, а также FROM.

Пример. Вывести данные из таблицы «Сотрудник» о сотрудниках чья зарплата больше, чем средняя зарплата всех сотрудников.

Листинг 41 – Выполнение подзапроса

SELECT * FROM Сотрудник
WHERE зарплата > (SELECT AVG (зарплата) FROM Сотрудник);

3. Общие табличные выражения (CTE

CTE – это временный набор результатов, который определяется в рамках выполнения одного оператора. CTE могут храниться памяти в ходе выполнения запроса, что позволяет избежать повторного выполнения одного и того же SQL запроса, если он используется несколько раз в основном запросе.

Базовый синтаксис CTE:

Листинг 42 – Общее выражение CTE

WITH <название виртуальной таблицы> AS (
SELECT <определение полей>
FROM <имя таблиц>
WHERE <условие>
)
SELECT * FROM <название виртуальной таблицы>

Реальные информационные задачи редко ограничиваются выборкой данных из одной таблицы, поэтому SQL предоставляет мощный набор операторов соединения, позволяющих объединять данные из нескольких связанных таблиц. Простейшим способом соединения является указание нескольких таблиц в предложении FROM с условием связывания в WHERE (эквисоединение — соединение по равенству столбцов).

Более современным и явным способом является использование оператора INNER JOIN, который возвращает только те записи, для которых найдены совпадающие значения в связующих столбцах обеих таблиц.

Для случаев, когда необходимо сохранить все записи из одной таблицы независимо от наличия соответствий в другой, используются левое соединение LEFT JOIN (все записи из левой таблицы, NULL при отсутствии соответствия справа) и правое соединение RIGHT JOIN (все записи из правой таблицы, NULL при отсутствии соответствия слева).

Перекрёстное соединение CROSS JOIN порождает декартово произведение таблиц, соединяя каждую строку первой таблицы с каждой строкой второй, и не требует условия ON. Полное соединение FULL OUTER JOIN объединяет результаты левого и правого соединений, возвращая все записи из обеих таблиц.

Помимо соединений, SQL поддерживает подзапросы (вложенные запросы), которые выполняются перед внешним запросом, а их результат используется для дальнейших операций; подзапросы классифицируются по способу получения результата (простые и коррелированные) и по виду результата (скалярные, строковые, табличные).

Дополнительным механизмом являются общие табличные выражения CTE, определяемые с помощью ключевого слова WITH, которые создают временный набор результатов, хранящийся в памяти на время выполнения запроса, и позволяющий избежать повторного выполнения одного и того же подзапроса при многократном использовании.

Таким образом, операторы соединения, подзапросы и CTE существенно расширяют возможности SQL, позволяя эффективно извлекать и агрегировать данные из сложных, нормализованных баз данных с множеством связанных таблиц.
